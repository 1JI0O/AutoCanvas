# 直播签到提醒

WebUI 左侧“点名与二维码”下方的“签到提醒”可编辑课程、收件人和邮件服务，修改后写入 UTF-8 YAML 文件并自动生效。无需重启；直接用编辑器修改文件也会生效。页面不会在轮询时覆盖尚未保存的表单；外部修改后需重新载入配置。

## 课程文件

位置为 `<runtime>/notifications/courses.yml`，课程编号须加引号，名称仅供邮件展示，编号决定实际检测范围。

```yaml
enabled: true
poll_seconds: 60
courses:
  '93921':
    name: 算法设计
    enabled: true
    recipients:
      - student@example.com
      - another@example.com
  '93124':
    name: 毛泽东思想和中国特色社会主义理论体系概论
    enabled: false
    recipients: []
```

只有总开关和该课程开关都为 `true`、课程在系统中仍为 active，才连接直播。启用的课程必须填写收件人。空课程列表不检测任何课程。提醒独立于全局媒体自动化暂停，因此无需开启回放处理、语音模型或自动扫码签到。

每 `poll_seconds` 秒刷新这些课程的直播列表，直接使用官方直播查询，不触发回放下载、作业同步或语音识别。该间隔限制为 30–3600 秒，默认为 60 秒，每轮查询完成后再计时。学校尚未开放的直播不能提前访问；正式上课时间到课结束期间观察已有直播记录，每 0.5 秒抽取最新画面并识别二维码。网络延迟和识别失败仍可能漏检。

只接受已有检测器验证过的本课程移动课堂签到二维码。语音里出现“签到”不会触发这项提醒，普通二维码和回放二维码也不会触发。语音关键词识别是另一个依赖 ASR 的功能。

## 邮件文件

位置为 `<runtime>/notifications/smtp.yml`：

```yaml
enabled: true
host: smtp.163.com
port: 465
security: ssl
user: sender@163.com
password: YOUR_SMTP_AUTHORIZATION_CODE
```

使用 [Python 标准库 SMTP 客户端](https://docs.python.org/3/library/smtplib.html)连接邮箱提供商，无需另装依赖或搭建 SMTP 服务器。支持 SSL/TLS 和 STARTTLS，验证服务器证书。使用邮箱的 SMTP 授权码。页面授权码留空会保留已保存的值，接口不返回授权码。禁用发送时将 `enabled` 设为 `false`。文件新建时目录权限为 0700，文件为 0600，均位于默认忽略的 runtime 中，不能通过产物下载接口读取。

邮件逐个收件人发送，不公开其他收件人的地址。内容包含课程、检测时间和课次，不包含原始签到 URL 或签到 token。测试按钮只向该课程已保存的收件人发送标有“测试”的邮件，不产生检测记录，不执行签到。测试操作每分钟最多一次。

## 记录与去重

- 识别记录保存在 SQLite 的 `attendance_detections`；邮件状态在 `reminder_deliveries`，页面展示最新 300 条，数据库保留全部。
- 同一课程、课次、签到编号只记录一次。旋转 token、多画面重复识别和正常重启不会重复提醒。检测发生时确定收件人；后续新增收件人不会补发历史事件。
- 同次签到仅留第一张截图，路径为 `outputs/<course>/<lecture>/live/attendance/<hash>.jpg`；同目录 `events.jsonl` 保存不含 token 的识别记录。此功能不保存连续视频或常规抽帧。
- 数据库和证据目前没有自动清理规则；只对实际解码成功的签到事件保存截图。
- 发送前重新检查课程和收件人；已关闭或移除的取消。SMTP 关闭时排队等待，超过十分钟的提醒过期，不再发送。
- `sent` 表示 SMTP 服务接受，不保证进收件箱；发送失败或结果不确定会留下记录，不自动重发。进程发送中断后标记 `unknown`，避免重复邮件。修复配置后可用测试按钮核对，历史失败不会自动补发。
- 检测和提醒不会调用学校扫码提交接口。自动签到仍由“点名与二维码”的独立开关控制；仅提醒部署应保持该开关关闭。
